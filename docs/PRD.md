# Pinkongpicture 本地测试版产品需求文档

版本：0.1

状态：依据已确认访谈整理。用户已批准按开发计划实施，本地软件流程已进入验证；真实照片效果与已有 Excel 模板适配仍待验收。

## 产品目标

帮助品控员将工厂供货产品包装上的文字录入 Excel，减少重复抄写和核对时间。先在一台电脑上使用 CPU 运行 PaddleOCR，通过真实照片验证识别、分组、字段提取、人工复核和导出流程。

产品面向多数没有条形码、也没有内部物料编码或供应商货号的来料。每次来料独立登记，产品档案用于辅助匹配与校对。任何记录都必须由人员确认后才能正式导出。

首期通过确认记录积累产品资料和纠错样本，不自动训练或替换 OCR 模型。

## 用户与现状

主要用户为品控员。图片主要由手机现场拍摄，同一产品的名称、厂商、地址和批次信息可能分散在多张照片中。

完整业务预计每天处理 100—1000 件，既有逐件录入，也有批量处理。这个数量是业务背景，不是尚未验证的单机容量承诺。

规划起点是只有项目简介和 Git 忽略规则的仓库。本次开发在此基础上建立应用、数据模型和行为测试；实施情况见本地试用说明。

## 术语与记录边界

| 术语 | 定义 |
| --- | --- |
| 产品档案 | 某个产品的长期资料，由系统生成内部编号，人员确认关联 |
| 档案版本 | 同一产品的地址等资料发生变化时保留的新版本，不改写历史来料信息 |
| 来料记录 | 一次来料中一个产品、一个批号的登记，可关联多张照片 |
| 图片组 | 系统建议或人员整理的一组照片，是待核对的归组结果 |
| 确认记录 | 人员完成字段与图片归属检查后保存的来料记录 |
| 产品记忆 | 使用历史确认资料辅助产品匹配和字段校对，不代表模型参数更新 |
| 纠错样本 | 可以对应到图片文字区域的正确文本、区域截图和修改来源 |

同一产品、同一批号在不同来料中可以产生多条记录。不能用产品编号与批号简单去重，从而吞掉实际来料。

## 用户故事

1. 作为品控员，我希望一次导入多张手机照片，以减少逐张操作。
2. 作为品控员，我希望系统建议哪些照片属于同一条来料记录，以减少手工整理。
3. 作为品控员，我希望把不确定的照片放入待分组区，以免不同产品或批号被合并。
4. 作为品控员，我希望补拍、补充可核实信息并拖动归组，以处理只有局部信息的照片。
5. 作为品控员，我希望自动提取七个字段，以减少抄写。
6. 作为品控员，我希望查看字段对应的原图位置，以快速判断识别是否正确。
7. 作为品控员，我希望对照历史产品资料，同时看到本次照片的内容，以发现真实变化。
8. 作为品控员，我希望选择已有产品或建立新档案，以登记没有条码的产品。
9. 作为品控员，我希望不同规格和不同厂商的产品分别建档，以免资料混用。
10. 作为品控员，我希望说明包装未标注的信息，以完成有依据的登记。
11. 作为品控员，我希望记录手动补填的信息来源，以区别照片内容和外部资料。
12. 作为品控员，我希望保留包装原文和明确日期的统一格式，以兼顾追溯与导出。
13. 作为品控员，我希望每次来料独立留档，以保留来料历史。
14. 作为品控员，我希望修改记录时保留修改历史并重新确认，以追溯更正。
15. 作为品控员，我希望按日期或批次导出固定模板，以沿用现有 Excel 工作方式。
16. 作为品控员，我希望确认后的资料帮助下次匹配，并保留有效纠错样本，以减少重复修正并为后续训练积累数据。

## 核心流程

导入照片 → PaddleOCR 识别文字 → 自动建议分组 → 人员检查并调整 → 提取字段并匹配产品候选 → 对照当前图片与历史资料 → 人工确认 → 保存来料记录与相关样本 → 按模板导出 Excel。

用户可以返回修改分组或字段。调整照片归属后，需要重新检查受影响记录的字段，不能继续沿用来自另一组照片的确认结果。

### 图片导入与分组

- 支持逐件和批量导入，同一条来料记录可包含多张照片。
- 依据识别到的产品信息和批次信息建议分组；外观和拍摄顺序只能辅助判断。
- 不同批号必须分开登记，即使产品名称、规格和包装相同。
- 无法确定归属的照片进入待分组区，不强制归入最相似的产品。
- 人员补拍，或手动补充能够区分产品的信息及其依据，再将照片拖入正确分组。
- 没有批号的照片可在有足够其他依据且人员确认后归组；不得自动虚构批号。

### OCR 与字段提取

PaddleOCR 负责读取文字及位置。提取层使用标签关键词、文字位置和历史产品资料，将文字归入目标字段。第一版不引入语言模型。

OCR 的识别分数只作为复核提示，不视为字段正确概率，也不用于绕过人工确认。

品牌名与产品名称、委托方与生产厂商、注册地址与生产地址必须区分。出现多个合理候选时，交由人员选择。

### 字段规则

| 字段 | 保存与处理规则 |
| --- | --- |
| 产品名称 | 保留本次提取及确认结果，不能仅凭历史资料覆盖 |
| 规格 | 参与产品区分并导出 Excel；具体格式随真实包装确定 |
| 生产厂商 | 区别于供应商和委托方；厂商变化建立新产品档案 |
| 生产地址 | 与当前图片核对；仅地址变化时，经确认增加档案版本 |
| 批号 | 每次重新读取；同次来料的不同批号分别登记 |
| 生产日期 | 保留原文，对含义明确的日期统一格式，不反推缺失部分 |
| 保质期 | 保留原文和明确的单位；不能将到期日期擅自转换成保质期 |
| 录入时间 | 系统记录固定时间，采用北京时间；不使用随打开日期变化的公式 |
| 操作人 | 记录本次确认人员；本地测试版的身份输入方式待确定 |

包装写“见封口”等指示文字时，需要查看对应照片或补拍，不能把指示文字当成实际日期。

包装确实未标注的字段允许标记“未标注”并说明原因。照片看不清与包装未标注是不同情况；看不清时需补拍，或依据可核实资料人工填写并保存来源。两类情况均不得默默猜补。

### 产品匹配与历史资料

- 系统按名称、规格和厂商等信息提供历史候选，由人员确认关联或新建档案。
- 产品内部编号由系统生成，不要求包装贴码。
- 规格不同或厂商变化时，新建产品档案。
- 同一产品仅地址变化时，人员确认后建立档案新版本，既有来料记录保持原值。
- 现有识别内容与历史资料并列显示，明显差异和看不清的内容需要人工处理。
- 批号、生产日期和保质期不能直接从上次来料复制。

### 确认与修改

待确认记录可以继续编辑，只有完成确认的版本进入正式导出范围。确认前需检查图片归属、产品关联、七个字段以及缺失说明或补填来源。

已确认记录允许修改，保存修改人、时间、原因及前后内容。修改后的内容重新确认后才能作为最新版本导出；重新确认前不得将未确认的修改内容导出为正式记录。

原有导出文件保持不变。重新导出生成当前筛选范围内的已确认内容。

### 产品记忆与训练样本

确认资料进入产品档案和来料历史，供后续识别匹配与校对使用。纠错样本需要保存文字区域截图、对应正确文本、OCR 原文及来源关联。

只有能与图片文字对应的纠错才进入训练候选样本。从送货单等资料补填、或者其他人员依据外部资料修改的内容，仅记录业务来源，不自动作为原图训练标签。

保存样本不触发模型训练，不承诺每确认一次就提高 OCR 精度。以后训练需另外整理样本并验证效果。

### Excel 输出

- 沿用用户已有固定模板，待取得模板后确定工作表、表头、单元格位置和格式。
- 支持按日期或批次筛选已确认来料记录后导出。
- 导出七个业务字段，以及录入时间和操作人。
- 每条记录的逻辑边界不随导出变化，不能合并掉不同来料或不同批号。
- 导出字段应与已确认记录一致，中文、批号前导零、日期和保质期单位应保持正确。
- 未标注字段及说明、日期原文与统一格式如何落到模板，待查看模板后确定，不擅自增加列。

## 本地测试版数据与技术边界

识别方案已确定为 PaddleOCR、CPU 和规则提取。具体 PaddleOCR 版本、模型、依赖版本、界面框架与本地存储实现，在开发准备和样本测试时确定，不在 PRD 中视为已选定。

本地测试电脑保存业务记录、产品档案、修改历史和纠错样本。导入照片在本地查看；应用不主动删除用户保存在手机或电脑上的原始文件。用于内部处理的临时副本与用户原文件应区分。

数据、图片、模型和导出文件不提交 Git。产品功能源码和文档由 Git 管理。

未来企业部署沿用以下已确认原则，但不作为首期交付内容：原始整图可临时传到自有服务器识别，结束后清除，不长期存储、备份或向其他人员展示；有图片依据的文字区域截图和纠错信息允许集中保存，属于明确的存储例外；人员共享记录和 Excel。

## 验收方案

以用户可见的完整流程作为主要验收边界：导入测试照片，完成分组与复核，保存记录，再打开导出的 Excel 核对结果。规则级检查只用于定位日期处理、归组或字段映射中的问题，不替代完整流程验证。

仓库尚无测试基础。测试方案如下，待开发时落实，不代表已经执行通过。

| 场景 | 预期结果 |
| --- | --- |
| 同一产品的正面、背面和批号照片 | 可归为一条记录，七个字段可追溯到对应图片或补填来源 |
| 同款产品出现两个批号 | 分别登记，不因外观一致而合并 |
| 只有背面且没有批号的疑难照片 | 无法确定归属时进入待分组区，允许补充依据后人工归组 |
| 同名同厂商、规格不同 | 分别建立产品档案，Excel 包含正确规格 |
| 厂商或地址改变 | 分别按新档案或新版本处理，旧来料信息不被改写 |
| 缺少批号或保质期 | 可说明未标注；看不清时要求补拍或有依据的补填，不猜测 |
| 同时出现委托方和生产商 | 不自动混为一项，不确定时让人员选择 |
| 日期原文、含糊日期或“见封口” | 保留原文，仅统一明确日期，不推算缺失信息 |
| 同一产品同一批号再次来料 | 能新增来料记录，不被简单去重 |
| 记录尚未确认 | 不进入正式导出结果 |
| 修改已经确认的记录 | 保留修改历史，重新确认后新导出采用新内容，旧 Excel 不变 |
| 图片对应的文字纠错 | 正确文字与区域截图关联，形成训练候选样本 |
| 从外部资料手工补填 | 保留来源，不形成原图的 OCR 训练标签 |
| 按模板导出 | 行数、字段位置和值与筛选的已确认记录一致，无错列、漏行或意外重复 |
| 正常关闭并重新打开应用 | 已保存档案、来料记录和修改历史可继续查看 |

### 识别效果与效率评估

使用人工核实的真实包装照片作对照，覆盖小字、反光、倾斜、多个信息面和不同批号。区分用于调整规则的样本与后续验证样本，避免只报告反复调试过的照片结果。

记录以下指标，并分别报告人工确认前和确认后的结果：

- 各字段的完整匹配率与一条记录全部七个字段正确的比例。
- 自动建议分组的正确性、错误合并情况和进入待分组区的比例。
- 每条记录需要修改的字段数、复核时间，以及相对现有人工录入的耗时变化。
- 每组图片识别与字段提取耗时、首次模型加载耗时及批量总耗时。
- Excel 行数、字段映射、批号和日期值的一致性。

将“未标注”和“无法辨认”单独统计，不能通过全部留空或全部交给人工来虚增准确率。照片看不清时，不承诺恢复不存在的可读信息。

业务准确率阈值尚未确定，需要结合真实照片和人工录入基线设定。首期先验证流程正确并测量结果，不预设虚构的百分比。

早期讨论的“5 人同时操作、每组 3 张照片、约 15 秒得到结果”保留为未来多人阶段的待测目标，不作为当前单机测试版验收门槛。CPU 单机实测后再决定硬件需求。

## 不在首期范围内

- 企业服务器采购与部署、厂外联网和域名配置。
- 多人账号权限、实时共享和并发冲突处理。
- 手机原生应用和直接远程拍照上传流程。
- 全自动免复核登记。
- 语言模型辅助字段抽取。
- OCR 模型训练、自动更新和训练管理界面。
- 条码识别、ERP 对接、库存数量管理及标签合规判定。
- 自动根据日期计算缺失的生产日期、保质期或到期日期。
